# 0.14.0-alpha / paper dashboard and Weather TV

Visual direction requested by owner: https://github.com/wesbos/photo-frame-dashboard . Inspected dashboard/index.html, css/tokens.css and css/views/home.css. Original native adaptation of warm paper/ink palette, strong condensed typography, serif date/editorial accents, large clock, thin rules, selected rail and information panels. No upstream scripts/assets/fonts copied or executed, no root/firmware/device scripts run. Reference dashboard uses mock data; this app does not copy mock people, presence, weather or chores.

Today replaces the launcher-grid Home: large clock/date, cached native-weather summary, actual local calendar entry, up to three open school assignments, and a real photo from an already loaded Immich selection or latest uploaded image. Empty states are labelled. Native weather widget never fabricates a temperature; only matching-location cached data is used, with retrieval timestamp and stale indication. No automatic Home forecast requests or automatic library-wide Immich fetch. Shortcuts retain School/Books/Create/Games/Uploads/Explore and add Weather TV. Layout stacks on narrow displays rather than hard-coding the reference's 1280-pixel stage.

Shared frame surfaces become warm paper and cream; labels/inputs/checkboxes and shared icons are adapted for dark ink. Native sans/serif fallbacks avoid remote-font requirements. Existing seasonal choices now influence accent colour while the paper base remains consistent; birthday greetings/decorative scenes remain. Some inherited thumbnail/fullscreen/native-dialog internals retain their prior specialised presentation; this is not a complete rewrite of every legacy component. No data/schema/dependency/signing changes.

Weather TV opens https://weatherstar.netbymatt.com/ (HTTPS version of owner-provided http://weatherstar.netbymatt.com/), WeatherStar 4000+, not an official Weatherscan broadcast. Source information: https://github.com/netbymatt/ws4kp documents background music. App embeds the public webpage; no music is copied/bundled, no invented live data or Weather Channel affiliation is claimed. Website's own location/music/settings controls apply and are not automatically linked to native Open-Meteo settings. Audio requires user interaction within the page; no promise of autoplay.

Opt-in third-party browsing, JavaScript/DOM storage enabled, app file/content access and geolocation bridge disabled, no app JavaScript interface or auth injection, HTTPS main-origin navigation restricted, default certificate checks retained and mixed content blocked on API 21+. Third-party data/audio resources and site storage are still used by the page. Main-page errors have native status and a compatible-browser fallback. A network success/page-finished event is not proof of functional JS, forecasts or audio. Stop/Done/page navigation/backgrounding destroys embedded WebView and stops its audio; external-browser playback is controlled by that browser. Foreground display stays awake.

The linked upstream sites target much newer browser features than an API 17 WebView can promise. Native dashboard remains independent of those features; external WeatherStar may be blank or nonfunctional. No Chromium/WebView update or separate server is installed. Existing native weather 403 issue is not claimed fixed by this addition.

Source-only proposal: compilation, old-device rendering, live rotation, data widgets, native contrast, weather page compatibility, website controls and music playback are unverified until CI/device tests. JSON School export remains export-only without a restore UI; local data should not be the sole copy of important schoolwork.
