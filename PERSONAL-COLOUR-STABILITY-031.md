# 0.31.0-alpha / app pins, imported colouring and layout stability

Adds Add app directly after Apps in the dashboard sidebar. Up to eight local pins have a 24-character name, an explicit installed launcher component and an icon from the same native monochrome CoreGlyph/DestinationIcon/ControlIcon families. Icon choices include visual previews. Long-press a pin to edit/remove it. Search uses installed launcher activities and launching rechecks component availability. Preferences commits are checked; uninstall/disabled apps produce a message rather than a crash. This is a local app launcher, not a URL or arbitrary intent editor.

Adds an imported colouring library through Create, Uploads and the Colouring chooser. PDF pages, image-based EPUB resources, CBZ/image ZIP collections and individual BitmapFactory-supported PNG/JPEG/GIF/WebP images can become freehand colouring pages. EPUB image references follow the spine where possible, then embedded raster images; it does not render reflowable text, CSS, vector-only SVG, DRM or remote images into colouring pages. CBZ pages use filename order and animated images use a still frame. No unrestricted etc-format support is claimed.

Sources are copied into private app storage; originals stay unchanged and no persistable picker grant is needed. PDF uses the existing legacy Pdfium engine: trusted documents only. Limits include 40 imports, 50MiB input, 200MiB library including ink, 300 pages, ZIP count/expanded-size checks, bounded XML/resources and sampled image decoding. Page colours are translucent freehand vector strokes saved atomically after strokes and on pause, with Undo, Clear, Save and page navigation. This is not flood fill, a colouring-PDF exporter or a complete EPUB renderer. A failed page/ink parse is not overwritten; save failures block intentional page changes but cannot prevent OS process death. Existing built-in studio/projects and bookshelf imports remain separate and unchanged.

The tablet shake has a concrete code-level conflict: UnifiedActivity.normalize calls normalWindow for every layout, clearing fullscreen, while the application fullscreen controller reapplies it. PersonalActivity overrides that old clearing path to request the single controller instead. The application controller also removes viewport/keyboard-size polling and global-layout fullscreen toggles, using lifecycle, focus and UI-visibility events with idempotent flag changes. Focused EditText temporarily uses ordinary system bars for stable legacy text input; fullscreen resumes when editor focus ends or a nonediting page opens. Keyboard dismissal alone can leave bars visible while the editor retains focus. Gesture and vendor restrictions remain.

The launcher implementation is PersonalActivity, inheriting existing calendar/photos/weather/cast behavior. An activity-alias retains the previous CalendarPhotosActivity launcher/Home component name for existing launcher shortcuts. ColouringBookActivity is internal/nonexported. Foreground weather epoch tracking remains intact. No new Android permissions or dependencies are added.

No Android build, tablet reproduction or device test was run.
