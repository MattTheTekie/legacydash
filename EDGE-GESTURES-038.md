# 0.38.0-alpha / invisible cross-app edge gestures

Adds Settings > Gestures / invisible edge controls. This is an opt-in separate overlay service, not a gesture detector limited to legacydash and not part of the floating pet. Default is disabled. Once enabled with overlay permission, a transparent left/right edge strip remains while Skylight/other apps are foreground. Defaults: left-middle, 16dp wide, 160dp high, 64dp inward travel. Edge, top/middle/bottom placement, width, height and travel threshold are saved via checked preferences commits.

Three predefined gesture slots are configurable: one-finger inward swipe (under 1.2s), double-tap edge and hold at least 650ms then release. Each can do nothing, return to the existing legacydash task or launch an explicitly chosen installed launcher component. Default is inward swipe -> legacydash; the other slots do nothing. This is not arbitrary recorded/freeform gesture recognition, Home/Back key injection, an accessibility service or a root event hook. To switch both ways, assign another gesture to the actual installed Skylight launcher entry. Returning to legacydash restores its task, not necessarily the dashboard Home page.

Only touches beginning inside the small enabled strip are captured; they are consumed even if no gesture is recognized and are not replayed into the underlying app. Outside touches pass normally. There is no visible normal-mode handle, panel, trail or full-screen touch catcher. A voluntary ten-second test shows a translucent strip and recognition toast instead of executing app actions. Move/narrow/disable it if it conflicts with content. Multi-touch cancels recognition and launch actions have a brief cooldown.

Adds SYSTEM_ALERT_WINDOW and a nonexported foreground service. Android 4-era windows use TYPE_PHONE; API26+ uses TYPE_APPLICATION_OVERLAY. API23+ requires the user's overlay permission grant; older firmware still must allow the declared permission/window. The service starts from visible app interaction/resume only when the saved opt-in is enabled. An ongoing notification identifies it and offers Disable; invisible gesture does not mean a hidden service notification. Settings also provides disable/reset and permission/status controls. No root grant, app-ops manipulation, accessibility access, screen capture, credentials interception, remote control or network endpoint is added.

The service can request sticky restart after process reclamation, but vendor killing, permission revocation and force-stop may prevent this. There is no boot receiver: open legacydash after reboot to restore a previously enabled strip. Newer Android/background-launch/overlay restrictions and Skylight kiosk policies may block it; modern OS compatibility is not guaranteed by a guarded window type alone. It cannot override secure/system windows, lock screens, firmware restrictions or create native navigation bars. Existing installed-app export/enabled status is checked before external launches.

No Android build, device test or Skylight reproduction was run. Verify CI, Android4 overlay grant/window type, enable/disable/notification recovery, truly transparent hit region, test timeout, gesture thresholds, action persistence, installed-app selection, switching in both directions, rotation, service lifecycle, keyboard/secure-window behavior and existing app features.
