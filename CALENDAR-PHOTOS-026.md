# 0.26.0-alpha / calendar sizing and saved photos

Replaces the old small CalendarView path with CalendarPane, a workspace-sized month grid and day-entry editor. The actual measured width/height chooses stacked portrait versus side-by-side wide layout. Six equal-height week rows expand with the available month viewport; cells, day text and optional entry previews grow on larger screens. A scrollable minimum row size/font-scale allowance avoids shrinking the month into an unreadable strip on short windows. The calendar hides the redundant page header/pet footer to use the available workspace. Month arrows, Today, locale first weekday, adjacent-month dates, selected/today styling and saved-entry indicators are native controls.

Existing event.YYYY-MM-DD values remain the data source. Selected day is remembered. Day edits autosave after a pause and flush on selection, page departure and backgrounding. Commit failures show NOT SAVED, prevent switching the selected day and retain session drafts. They do not provide durable crash recovery if storage is failing or the process is killed. There is no external calendar sync or event/reminder service.

Album IDs already persisted, but Home formerly read only the in-memory mediaItems list and the saved-session restore callback never repopulated/refreshed its photo panel. SavedPhotoPreview now binds directly to the real selected source and automatically loads after encrypted session restore without navigating away from Home or resetting the selection. It requests a bounded first-page preview from each selected album until it finds an image, with a video thumbnail fallback. Whole library and uploaded-photo source choices remain supported. Home updates in place; authenticated Photos opens the actual saved-selection library automatically. If Photos was opened during restoration, it proceeds to that library when the same saved session becomes available.

Album cards save each tap with a checked preferences commit; no Apply step is required. Empty selection explicitly means Whole library, matching existing behavior. Preview jobs are debounced and results are checked against the current source/session so stale work cannot update a different account or changed selection. Thumbnails are bounded/sampled and cached in memory for five minutes, not stored as a new offline photo library. Reopening without network still requires the remote server to show a remote preview; failures are labelled instead of asking the user to rechoose albums.

Authentication continues to use the existing encrypted SessionVault. API18+ attempts automatic restoration; API17 still requires its separate unlock passphrase. No new plaintext credential storage is added. Explicit sign-out/forget retains its existing selection-clearing behavior. The legacy 5,000-item/100-request library bounds and thumbnail API compatibility limits remain. Preview fetching is separate and bounded to first pages; the preview is not a complete album inventory.

No Android build or device test was run here. Verify CI, calendar measured layout/font scaling/keyboard/rotation, existing entries and save failures, startup vault restoration, source/album persistence after force-close/reopen, rapid toggles and navigation, sign-out/account changes, local photos, remote errors, video-only albums, and unchanged spatial notes/casting/music/kiosk behavior.
