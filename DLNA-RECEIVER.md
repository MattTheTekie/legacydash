# 0.9.0-alpha / foreground DLNA-UPnP receiver

Implements receiver source directly on main. Repository inspection found only main and no open pull requests; no other branch existed to merge or delete. Existing weather, icon/album, PDF, book, project, game, gallery and upload sources retained.

This is an untested UPnP AV media-renderer implementation, not a DLNA-certified product and not a claim of compatibility with every controller. No successful build, discovery test, playback test or security audit has been performed here. Test with an actual controller and the SKY002 before relying on it. API 17 minimum retained.

Home / Cast receiver lets user choose a private IPv4 interface and receiver name, then explicitly enables SSDP discovery. Provides MediaRenderer device/SCPD descriptions, AVTransport, RenderingControl and ConnectionManager control endpoints; play/pause/stop, REL_TIME/ABS_TIME seek, volume/mute and status queries. HTTP event subscriptions with LastChange notifications and bounded expiry; event callbacks restricted to the subscribing peer's address. No automatic startup, no background receiver service: navigating away, backgrounding or Stop Receiver closes discovery/control and playback.

Receives sender-provided HTTP(S) media URLs. Native image display and Android media playback for music/video, now-playing text, local controls, seek/volume sliders and fullscreen receiver screen. No Miracast, Chromecast, AirPlay, DRM, screen mirroring, casting out to TVs, playlists/NextAVTransportURI, or guaranteed HLS/transcoding support. The phone/controller must expose a reachable media URL; local files that exist only on the phone need the controller's file-serving feature. Codec/TLS support depends on old Android/vendor firmware.

Security: trusted LAN only. Standard local discovery/control is unauthenticated and unencrypted. Any reachable LAN device can change media or control playback while enabled. Receiver fetches HTTP(S) URLs supplied by controllers, including LAN or Internet URLs; it is not a hardened network sandbox or an SSRF isolation boundary. No file/smb/content URI scheme or credential-in-URL accepted for transport; application Immich tokens are never added to cast requests. Photo download cap twenty MB and sampled decode, bounded HTTP headers/control bodies, two client workers plus bounded queue, XML DOCTYPE/depth/event checks, maximum eight event subscriptions. These limits do not constitute a security audit. Never port-forward or expose the receiver publicly.

SSDP uses 239.255.255.250:1900, an ephemeral HTTP port on the selected address, Wi-Fi multicast lock and alive/byebye announcements. Client isolation, multicast filtering, firewalls or VLANs can prevent discovery. Uses new ACCESS_WIFI_STATE and CHANGE_WIFI_MULTICAST_STATE permissions. No third-party receiver binary/dependency added.

The native media-renderer/SCPD implementation is deliberately small and may need standards/interoperability fixes after controller testing. GENA events reflect state/volume changes; no certification or universal sender compatibility is claimed. Existing build/release workflow will attempt the new version after commit; publication is conditional on build success. Development signing and legacy dependency/PDF warnings still apply.
