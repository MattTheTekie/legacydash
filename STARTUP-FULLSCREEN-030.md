# 0.30.0-alpha / startup weather and fullscreen

Opening the dashboard or returning from a fully backgrounded app now requests fresh native weather even when the existing cache is younger than 15 minutes. Existing cached values remain visible until success; failures preserve the previous cache. The normal 15-minute refresh scheduler, offline retry delay, saved-location checks and Home/detail updates remain. No selected location still means no weather download.

LegacyDashApp tracks started activity count and a foreground epoch, distinguishing a normal in-app activity transition from an app return after all app activities stopped. ForecastRefresh consumes one forced request per observed foreground epoch. The dashboard scheduler remains lifecycle-bound: it is not a background service and does not run while the dashboard is paused, including while a separate cast/kiosk activity owns the foreground. Returning to the dashboard catches up; internal activity switches do not intentionally force another fresh download. A newly recreated dashboard instance also performs its initial fetch. Returning from external pickers/apps counts as a foreground return. Existing in-flight automatic requests are not duplicated simultaneously; a pending new foreground request waits for the prior automatic request to finish.

SkyTheme defaults to windowFullscreen=true. Application lifecycle callbacks apply fullscreen to every app-owned activity, including the dashboard, cast player and weather kiosk. API19+ also requests immersive-sticky navigation hiding; API17-18 retain normal navigation controls while hiding the status bar. Global-layout/system-UI visibility hooks restore mode after older page code clears fullscreen flags, and listeners/callbacks are removed on activity destruction. Unrelated system UI flags remain intact.

System bars are not permanently locked out. Native gestures, permission/system dialogs, vendor navigation policies and the keyboard can reveal them. The controller temporarily releases fullscreen while its visible-frame heuristic detects a keyboard, allowing legacy text-entry resize behavior; it restores fullscreen after that keyboard closes. The keyboard heuristic and Android/vendor support are not device-verified, especially in multi-window/floating-keyboard cases. External browser/file-picker windows are not controlled. No kiosk lock-task mode, device-owner permission, new service or new Android permission is added. Existing fullscreen content controls are unchanged.

No Android build or device test was run. Verify CI, fresh-cache cold launch/foreground return, intra-app cast/kiosk transitions, offline startup, 15-minute scheduling, all-page status bars, gestures, dialogs, keyboard editing/closing, rotation, API17/19/current Android and listener cleanup.
