# 0.27.0-alpha / Home photo preview quality

The prior preview loader repeatedly halved each image until both dimensions fell under a fixed 900x700 ceiling. For example, a 1440x1080 preview became 720x540 even when a wider card required more detail. This patch waits for the actual ImageView content size in physical pixels and chooses the largest power-of-two sample that still covers both target dimensions, subject to a separate heap-based safety budget. It explicitly uses ARGB_8888, disables density-based bitmap rescaling and enables filtered display scaling. This is not AI enhancement and cannot restore detail absent from the source.

The preview cache records the requested display dimensions rather than only the album source. A larger card or rotation triggers a debounced quality reload; a smaller card reuses the existing adequate cached request. Unchanged bitmaps are not repeatedly reassigned. An already displayed bitmap remains while the same source receives a quality upgrade. Source/session changes still clear old content and discard stale results. Fetching waits for a measured visible-page target instead of downloading a fixed-size image before layout.

Immich preview remains the first request. If the returned image dimensions cannot cover the card and the asset is a photo, the loader tries thumbnail?size=fullsize. Unsupported versions, redirect responses, oversized files, decode failures and memory pressure retain the normal preview. It does not follow authenticated cross-server redirects, fetch original videos, change server image-generation settings or guarantee that a server supports fullsize. Video-only albums retain their still-preview fallback. Existing credential handling and saved-album restoration remain unchanged.

Downloads are bounded by heap size (2-12 MiB); decoded image budgets are independently bounded (2-12 MiB, based on max heap /24), with power-of-two sampling if required. Requested target dimensions cap at 4096 pixels per axis. Low-memory devices, server preview compression/resolution, unsupported originals and extreme centre crops can still limit sharpness. Local uploaded photos use the same measured-size decoder; no new EXIF orientation pipeline is added.

No Android build or device/render test was run. Verify CI, phone/frame card dimensions, high-density displays, portrait images in wide cards, rotations/resize, repeated Home visits, saved-album restoration, API17 memory use and Immich fullsize fallback/redirect behavior.
