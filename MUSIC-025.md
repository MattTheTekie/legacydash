# 0.25.0-alpha / cast music now playing

The cast audio placeholder is replaced by a native record-style now-playing view. It shows supplied title/artist/album, artwork when available, actual playback position/duration and playback/pause state. A vinyl-style disc has circular cropped cover art at its centre, grooves, a fallback music-note label, a stationary tonearm and a cover-tinted dark gradient. It is an original visual treatment inspired by record-player music UIs, with no NetEase branding/assets or service integration. Layout adapts between side-by-side landscape and stacked portrait.

The disc rotates only while the prepared MediaPlayer reports isPlaying, freezes on pause and stops scheduling frames while hidden/detached/backgrounded. It uses an approximately 15fps invalidation schedule; this is an implementation limit, not a measured frame-rate guarantee. Existing tap-to-reveal controls, album quiet transitions, screen rotation and Back/Stop cancellation remain. The music view does not pretend to be a video or change decoder capabilities.

Metadata priority: UPnP/DIDL title, artist (creator fallback), album and albumArtURI. Relative artwork URLs resolve against the current media URL. Missing values may be filled from bounded ID3v2.3/v2.4 TIT2/TPE1/TALB/APIC data from the current HTTP(S) media resource. Text encoding variants and common unsynchronization are supported; compressed/encrypted/grouped unsupported frames are skipped. ID3v1, ID3v2.2, embedded MP4/M4A/FLAC artwork and online metadata services are not implemented.

Album artwork requests are limited to 5MiB; embedded tag probing requests at most the first 1MiB via Range and only reads an ID3 tag within that cap. A server that ignores Range may see its response closed after the tag/header, potentially logging a client disconnect. Read/connect timeouts, cancellation, response limits, sampled cover decode, a 40MP decode-dimension guard and at most three redirects limit work. HTTP(S) only, no URL userinfo, no HTTPS downgrade or injected app credentials. Metadata/art are fetched only from sender-supplied URLs or the cast media; there is no web cover search. Like the receiver itself this is trusted-LAN functionality, not protection against a malicious sender's arbitrary network URL choices.

If metadata is absent, the current filename is used as a fallback title rather than an invented song identity. Missing artist/album and missing cover are labelled. Unsupported, missing or oversized cover art does not fail audio playback. Metadata/art loads are background tasks keyed by media generation/URI/metadata, so stale results are discarded when the track changes. Covers remain bounded in memory and are not saved to a new media library.

No Android build or device test was run. Verify CI, API17 rendering, tagged/untagged MP3s, DIDL artwork URLs, embedded art, bad/large/redirecting artwork, metadata changes across tracks, pause/resume/seek, portrait/landscape fitting, lifecycle cancellation and unchanged video/photo casting and Back-to-stop behavior.
