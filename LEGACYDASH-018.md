# 0.18.0-alpha / networking and virtual companion

Upload UI no longer asks for an interface. It passes the wildcard IPv4 address to the existing UploadReceiver and advertises actual private LAN addresses using the same port and session secret. The QR uses one listed address, while the listener accepts all IPv4 interfaces. This does not claim IPv6 support. Existing import validation, size/storage quotas, secret URL/header, 15-minute expiration and stop-on-leave/background behavior remain. Wildcard binding increases exposure: anyone who can reach the listener and has the secret URL may upload; trusted networks only. No router ports are opened.

DLNA receiving now belongs to CastService, not the activity page. It starts by default when the app opens, uses an ongoing foreground notification with Open/Stop, preserves an explicit disabled preference, and rescans private IPv4 addresses every 15 seconds. A renderer is attempted on each private IPv4 interface with one shared UUID and mirrored transport state. Interface failures are reported. Activity page/pause cleanup of the old renderer does not own these service instances. The service owns media preparation, playback, volume and photo loading; the receiver panel attaches/detaches a video surface without stopping service playback. An incoming photo/video need not forcibly replace an editor: open the panel or notification to view it. This is DLNA/UPnP only, with no pairing/password or Google Cast/AirPlay/Miracast support. Sender-provided HTTP(S) media URLs are fetched. Use a trusted LAN only.

Persistence is subject to Android/firmware background, notification, network and power restrictions. No guarantee survives force-stop, reboot, denied service startup or process termination, and no boot receiver is installed. Notification permission behavior and newer Android foreground-service restrictions are unverified. Private-IPv4 SSDP multicast may fail on VPNs, isolated Wi-Fi or particular interfaces; codec and stream compatibility remain device-dependent.

The virtual companion now has saved food/fun/energy/cleanliness/health, sleeping/waking, training XP, age/care-dependent growth, feeding/cleaning/medicine and a five-tap timed play activity. Legacy food/XP seed the new local pet store once. Time advances on opening/drawing with a capped 24-hour catch-up; there is no background pet timer or death mechanic. Idle bobbing, blinking, stepping, sleep and care reactions are native animations. It is an original local pet, not a Digimon emulator.

A small animated pet is considered only for the bottom-right empty content region. Visible text, controls, images, custom canvases and media block docking; it hides rather than cover them, and also hides in content workspaces, galleries and fullscreen. It may be absent when there is no empty region, especially on small screens. Pet access remains in Games. The pet can be disabled in its care screen. Animation callbacks stop on detach/background.

Restores normal-width labelled navigation when rotating back from compact landscape, and makes card-column calculation account for rail width and font scale. This is not an exhaustive responsive-layout rewrite.

Source-only: no Android compilation, network interoperability, lifecycle, media playback, pet-state, docking, IPv4 multihoming, notification or device tests were run here. CI and actual-device verification remain required.
